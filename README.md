# Backend-приложение для управления личными финансами на Java

Консольное приложение на языке Java. Несколько пользователей, личные кошельки,
доходы и расходы, категории, месячные бюджеты, уведомления, отчёты и обмен файлами.
Во время работы данные находятся в памяти. Между запусками аккаунты и кошельки
сохраняются в JSON.

Проект использует Java 17 и стандартную библиотеку.

## Сборка и запуск

Требуются **JDK 17** или новее, **Maven 3.9+** и терминал с UTF-8. При первой сборке нужен интернет для загрузки Maven-плагинов и JUnit.

```bash
git clone https://github.com/am-i-right/financial_app_backend_application.git
cd financial_app_backend_application
mvn clean verify
java -jar target/finance-app.jar
```

`verify` компилирует приложение, запускает все unit- и интеграционные сценарии JUnit,
собирает JAR и проверяет стиль. Интеграционные тесты называются `*Test` и запускаются
Surefire вместе с остальными. 

В IntelliJ IDEA откройте `pom.xml`, выберите JDK 17+ и запустите `com.myfinance.Main`.
По умолчанию папки `data/` и `exports/` находятся в рабочей директории приложения.
При необходимости их можно задать явно:

```bash
java -Dfinance.dataDir=data/demo -Dfinance.exportsDir=exports/demo -jar target/finance-app.jar
```

Логины чувствительны к регистру, пробелы по краям логина обрезаются. Пароль — минимум
8 символов, не только пробелы. Регистр и пробелы пароля значимы. Ввод пароля в консоли виден.
После регистрации нужно отдельно войти. Чтобы сменить пользователя, сначала выйдите из аккаунта.

## Команды

До входа: `1` — регистрация, `2` — вход. `11` и `0` доступны всегда.
После входа:

| Команда | Действие |
| --- | --- |
| `1` | Создать категорию: тип `1` — доход, `2` — расход |
| `2` / `3` | Добавить доход / расход |
| `4` | Установить или изменить бюджет категории за месяц |
| `5` | Общий баланс за всё время |
| `6` | Операции по дате, от ранних к поздним |
| `7` | Текстовый отчёт за выбранный месяц |
| `8` | Список категорий |
| `9` | Сохранить кошелёк и выйти из аккаунта |
| `10` | Операции по абсолютной сумме, по возрастанию |
| `11` | Справка с форматами ввода и правилами файлов |
| `12` | Переименовать категорию, сохранив её историю и бюджеты |
| `13` | Удалить неиспользуемую категорию вместе с её бюджетами |
| `14` | Выборка по нескольким категориям одного типа |
| `15` | Экспорт операций в CSV |
| `16` | Экспорт снимка кошелька в JSON |
| `17` | Импорт своего JSON-снимка с подтверждением замены |
| `18` | Сохранить месячный текстовый отчёт в файл |
| `19` | Удалить бюджет категории за месяц, сохранив операции |
| `0` | Сохранить изменения и завершить работу |

Сумма: `120.50` или `120,50`. Дата: `2026-11-09`. Месяц: `2026-11`.
В полях даты/месяца Enter означает сегодня/текущий месяц по часовому поясу компьютера.
Исключение — выборка `14`: пустой месяц означает всё время.

При ошибке приложение возвращается в меню: команду нужно выбрать заново.
EOF тоже вызывает сохранение. При ошибке записи успешное сохранение не заявляется.
После неудачного `0` можно повторить выход, а после неудачного `9` аккаунт остаётся активным.
Если EOF уже получен, приложение сообщает о неудаче записи и завершает работу.

## Пример работы

После регистрации пользователя и входа:

1. `1` → `Зарплата` → тип `1`; затем `1` → `Еда` → тип `2`.
2. Доход: `2` → `Зарплата` → `10000` → `2026-11-01`.
3. Бюджет: `4` → `Еда` → `2026-11` → `4000`.
4. Расход: `3` → `Еда` → `500` → `2026-11-09`.
5. `5` показывает `Баланс: 9500.00 RUB`.
6. `7` → `2026-11` показывает расходы 500.00 и остаток бюджета 3500.00 RUB.
7. Переименование: `12` → `Еда` → `Питание`. История и лимит сохранятся.
8. Создайте расходную категорию «Такси». Выборка: `14` → тип `2` → количество `2`
   → `Питание` → `Такси` → `2026-11`. Результат: 500.00 + 0.00, итого 500.00 RUB.

Каждое название для выборки вводится **отдельной строкой** после количества категорий.
Повторные категории учитываются один раз; неизвестная категория или другой тип вызывают ошибку.

Бюджеты в отчёте отображаются таблицей «Категория | Лимит | Потрачено | Остаток», все суммы в рублях.
Ширина колонок подбирается по содержимому: длинные названия и большие суммы не обрезаются,
отрицательный остаток сохраняет знак. Та же таблица используется в текстовом экспорте.

### Файлы

В командах ниже имя по умолчанию можно принять пустым вводом:

- CSV: `15` → `operations.csv`.
- JSON: `16` → `wallet.json`.
- Импорт: `17` → `wallet.json` → `да` для замены. Любой другой ответ отменяет импорт.
- Текстовый отчёт: `18` → `2026-11` → `report.txt`.

Файлы находятся в `exports/` либо в директории из `finance.exportsDir`.
Для импорта поместите JSON в эту директорию. Вводится **только имя файла**:
буквы, цифры, точка, дефис, подчёркивание; максимум 100 символов.
Расширения соответствуют операции: `.json`, `.csv`, `.txt`.
Произвольные пути и символические ссылки запрещены. Экспорт в существующее имя заменяет этот экспорт.

JSON содержит версию формата `1`, владельца, категории, операции и все месячные бюджеты.
Паролей и хешей в снимке кошелька нет, чужие снимки импортировать нельзя.
Вначале весь файл проверяется во временном кошельке. Только после успешной проверки
и ответа `да` он заменяет текущий. Неудачный или отменённый импорт сохраняет прежний кошелёк.

CSV использует UTF-8, заголовок `date,type,category,amount`, ISO-даты, положительные суммы
с двумя десятичными знаками и тип `INCOME`/`EXPENSE`. Запятые, кавычки и переводы строк
экранируются по правилам CSV. Текстовый экспорт использует тот же генератор, что отчёт в консоли.

### Готовая демонстрация

Для **пустой** директории `data/demo`:

```bash
java -Dfinance.dataDir=data/demo -Dfinance.exportsDir=exports/demo -jar target/finance-app.jar < examples/demo-input.txt
```

Вымышленный аккаунт `demo` / `demoPass123`, доход 1000 RUB, расход 120.50 RUB,
бюджет 100 RUB за ноябрь 2026. Результат — баланс **879.50 RUB**, превышение **20.50 RUB**,
затем переименование категории, выборка и три файла экспорта.
Повторный запуск использует сохранённые данные, поэтому для повторения примера нужна другая пустая директория.

## Хранение и восстановление

```text
data/
├── users.json                    
└── wallets/
    └── <SHA-256 логина>.json      # Отдельный кошелёк с проверкой владельца
exports/
├── operations.csv
├── wallet.json
└── report.txt
```

`users.json` читается при запуске. Регистрация сохраняется сразу. Кошелёк загружается
после проверки пароля. **Отсутствие файла кошелька в текущей реализации интерпретируется
как пустой кошелёк**: это касается как ещё не созданного, так и удалённого/утраченного снимка.
Отдельного признака, позволяющего различить эти случаи, в модели пользователя нет.
При `9`, `0` и EOF кошелёк сохраняется. Перед переключением аккаунта предыдущий
кошелёк обязательно записывается, поэтому изменения всех пользователей сохраняются.

Имя файла кошелька — полный SHA-256 нормализованного логина.
Данные сначала полностью записываются во временный файл рядом с целевым, затем
заменяют целевой файл. 

## Финансовые правила и ограничения

- Один кошелёк на пользователя, одна активная сессия в консоли, одна валюта - рубли (RUB).
- Все суммы операций и лимиты строго положительные, с точностью до копейки.
  `12.100` принимается как `12.10`, а `12.101` отклоняется без округления.
- Баланс вычисляется из истории, отдельного поля баланса нет. Отрицательный баланс разрешён.
- Категории уникальны в кошельке без учёта регистра и внешних пробелов. Тип не меняется.
  Используемую в операциях категорию удалить нельзя; пустая удаляется со своими бюджетами.
- Бюджет привязан к паре «категория расходов + месяц с годом». Остатки и лимиты
  не переносятся автоматически. Повторная установка заменяет только выбранный лимит.
- Расход не блокируется при превышении. Сразу после операции показывается только новый
  наивысший порог категории: 80%, ровно 100% либо первое превышение.
  Отдельно показывается переход баланса в минус или к нулю. Несвязанные операции
  не повторяют старые предупреждения. Отчёт по-прежнему показывает текущие превышения.
  При установке или изменении лимита ниже уже понесённых расходов предупреждение выводится
  сразу, только для выбранной категории и месяца, без повторения остальных предупреждений.
- Допустимы прошлые и будущие даты; операции сразу участвуют в общем балансе.
  Отчёт/выборка за месяц используют дату операции, а не время ввода.
- Приложение рассчитано на один процесс. Нет блокировок между несколькими одновременно
  запущенными экземплярами и общей транзакции для нескольких файлов.
- Сохранение при штатном выходе и EOF; при аварийной остановке, отключении питания или
  принудительном завершении изменения после последнего сохранения могут потеряться.
- Нет REST, базы данных, переводов, мультивалютности, редактирования/удаления операций
  и CSV-импорта. Переводы оставлены возможным продолжением проекта.

## Тесты и CI

```bash
mvn test
mvn clean verify
mvn checkstyle:check
```

[GitHub Actions](https://github.com/am-i-right/financial_app_backend_application/blob/main/.github/workflows/ci.yml)
выполняет `mvn clean verify` на Java 17 и 21 при push, PR и ручном запуске.
Матрица включает Ubuntu и Windows, всего четыре сочетания ОС и JDK.
Сохранены Maven cache и отчёты `test-results-<os>-java-<version>`, например
`test-results-windows-latest-java-17`.

Checkstyle проверяет основной код и тесты: wildcard/неиспользуемые импорты,
порядок модификаторов, строки до 140 символов, табуляцию и пробелы в конце строк.
